# Stage 3 — visual comparison

Источники: три PNG владельца — desktop Dashboard, desktop Calendar и три мобильных экрана. Логотип/люди/числа референсов не являются данными приложения.

В `screenshots-stage3/compare-*.png` референс **слева**, настоящая реализация **справа**. Desktop нормализован по ширине 1440 с верхним crop 900px. Mobile: app-content crop из 1536×1024 mockup без status/hardware, нормализация ширины 390 и сравнение верхних 780px. Нижняя навигация проверяется отдельно в viewport captures; не подменяется рамкой телефона. Разный контент, длительности и даты отмечены как доменные различия, а не «точное совпадение».

## Первая итерация

Desktop: сохранены нужные области, но более длинные действующие названия, реальное меню и отсутствие вымышленных метрик меняют плотность.

Mobile Dashboard: P2 — KPI/actions занимали почти весь первый экран, визиты уходили ниже. Исправление: три приоритетных KPI, короткие actions в один ряд; review KPI остаётся на desktop/в меню.

Mobile Calendar: P2 — дублирующая брендовая шапка/подписи задерживали начало расписания. Исправление: на этом маршруте используется собственный заголовок, с сохранением «Ещё»; лишние summary/подписи убраны визуально.

Card details: настоящий modal, а не отдельная страница; нет вымышленных специалиста/кабинета, WhatsApp и дублирования записи. Согласие/identity fields сохраняются. Footer не перекрывает content. Наличие второго закрытия — сохранённый общий modal contract, дальнейшая UI-полировка отдельно.

## Подтверждённые ограничения

Нет клиентских фотографий — используются инициалы; нет временного ряда выручки — не нарисован фиктивный график; сервисная панель заменяет отсутствующую модель специалистов. Кнопки ведут только на действующие routes. Исходный month по умолчанию сохранён; недельный reference state выбран явно для screenshot.

Финальные post-fix captures повторно сравнены в корневом `design-qa.md`: внутренний visual QA PASS, приёмка владельца ожидается. Три мобильных KPI и один ряд коротких действий возвращают приёмы в первый экран; date toolbar остаётся рабочим. Показ всего выбранного дня назван корректно: «Приёмы на выбранный день», а не только будущие визиты.

Desktop form state сохранён отдельно в `calendar-form-1440.png` и `compare-calendar-form.png`. Reference использует правую панель; в существующем продукте сохранён центрированный native modal с прежними фокусом, busy protection и consent — намеренное ограничение безопасной эволюции общего компонента.
