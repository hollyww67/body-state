# Воронка записи

Клиентские действия используют существующий Umami. Требуются согласие
`privacy-analytics=accepted`, настроенные `NEXT_PUBLIC_UMAMI_ID` /
`NEXT_PUBLIC_UMAMI_SRC` и загруженный трекер. При отказе, недоступном хранилище,
блокировщике или сбое трекера запись продолжает работать без отправки события.

| Событие | Источник и условие |
| --- | --- |
| `service_selected` | Выбор направления; для направления, выбранного по умолчанию или отдельной страницы, первое взаимодействие с доступным временем |
| `slot_selected` | Выбор доступного слота в форме, не административный перенос |
| `booking_created` | Успешный ответ сервера с сохранённой записью |
| `online_payment_started` | Получена ссылка от сервера, непосредственно перед переходом к оплате |
| `payment_confirmed` | Только внутренний отчёт: банковское подтверждение, записанное в `orders.paid_at` |
| `appointment_attended` | Только внутренний отчёт: явная отметка `attendance=present` и существующая запись в `client_visits` |

Внешний payload содержит только `website`, `name`, условный `url=/booking-flow`
и общий `title=Booking flow`. Названия процедур, реальные URL, query/hash,
имя, контакты, стоимость, здоровье, идентификаторы записей и аккаунтов не передаются.
`identify()` не используется. Автоматический сбор страниц отключён через
`data-auto-track=false`: иначе маршрут записи или token на success-странице
могли бы попасть в данные трекера. Для страниц управления записью и платежа
также установлены `no-referrer` и запрет индексации.

Идентификатор для защиты от повторного события хранится исключительно локально
в `sessionStorage`, отдельно для каждого типа события. Это дедупликация в пределах
вкладки/сессии, а не глобальный счётчик уникальных клиентов. При отсутствии трекера
события не буферизуются и могут быть потеряны; это не влияет на бронь.

Сервер не передаёт события Umami и не обходит отказ клиента. Внутренняя сводка
`/admin/dashboard` → «Воронка» считает факты выбранного московского дня. Это
разные события дня, а не когортная конверсия: платёж сегодня может относиться
к записи вчера. Считаются три направления с временными слотами; ручные ссылки,
не связанные с записью, и начисления за них не подменяют отметку посещения.
Открытие `/payment/success` и истечение времени сами по себе не считаются оплатой
или посещением. Подтверждённая ранее, а затем возвращённая оплата остаётся фактом
подтверждения в день `paid_at`, не показателем чистой выручки.

Проверка: интеграционный набор проверяет отказ от аналитики, дедупликацию,
точный обезличенный payload, поддельный callback, сумму платежа и явную посещаемость.
Перед отдельной внешней приёмкой нужно проверить Network на тестовом Umami:
без согласия нет запросов; после согласия payload не содержит реального маршрута
или идентификаторов. На localhost этот релиз отключает внешнюю аналитику.

Реализация опирается на официальный контракт [объектного payload](https://docs.umami.is/docs/tracker-functions)
и [отключения автоматического трекинга](https://docs.umami.is/docs/tracker-configuration).
Установленный внешний экземпляр Umami в этой работе не перенастраивался и не проверялся.
