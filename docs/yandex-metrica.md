# Яндекс Метрика — body-state.ru

## Подготовка

1. В кабинете [Яндекс Метрики](https://metrika.yandex.ru/) владелец сайта создаёт счётчик с адресом `https://body-state.ru`.
2. Номер счётчика **113557210** уже задан как значение по умолчанию в интеграции. При необходимости его можно переопределить через `NEXT_PUBLIC_YANDEX_METRIKA_ID=113557210` в окружении **перед сборкой Next.js**.
3. Пересобрать и перезапустить Next.js на сервере. Публичные переменные `NEXT_PUBLIC_*` встраиваются в клиентский bundle на этапе сборки.
4. При необходимости сохранить `NEXT_PUBLIC_UMAMI_ID` и `NEXT_PUBLIC_UMAMI_SRC`: существующий Umami теперь также загружается только после согласия.

## Как устроено

- Компонент `src/components/AnalyticsConsent.tsx` показывает выбор «Разрешить» / «Отказаться», сохраняет решение локально и позволяет изменить его в футере.
- Пока аналитика не разрешена, клиентские скрипты Яндекса и Umami не загружаются. Отзыв согласия приводит к перезагрузке, чтобы остановить работающие скрипты.
- Для Яндекс Метрики используется `defer: true`, а просмотр маршрута учитывается один раз через `hit` при изменении `pathname` Next.js. Параметры URL и фрагменты не передаются.
- Вебвизор и карта кликов выключены, содержимое пользовательских полей и личные данные в цели не отправляются.

## Цели

В интерфейсе Метрики откройте «Цели» → «Добавить цель» → «Целевое событие» и создайте цели **с точно такими идентификаторами**:

| Название | Идентификатор события | Где отправляется |
| --- | --- | --- |
| Успешная заявка на консультацию | `contact_request_success` | `src/app/contact/page.tsx`, после успешного ответа API |
| Успешная запись БФМ | `booking_bfm_success` | `src/components/BfmBookingForm.tsx`, после успешного ответа API |

В будущем через `trackMetricaGoal("event_name")` можно добавить цели для подтверждённой оплаты и других конверсий. Никогда не передавать ФИО, телефон, e-mail, диагноз, свободные заметки и идентификаторы заказов как параметры Метрики.

## Проверка

1. Открыть сайт в режиме инкогнито без предыдущего согласия. В Network **не должно** быть запросов к `mc.yandex.ru` или Umami.
2. Нажать «Отказаться». Убедиться, что запросов к аналитике всё ещё нет.
3. Открыть «Настройки аналитики» в футере и нажать «Разрешить аналитику». После этого запрос к `mc.yandex.ru/metrika/tag.js` должен появиться.
4. Перейти по нескольким страницам Next.js: просмотры должны появиться в Метрике без дублей.
5. Отправить тестовую заявку / запись и проверить срабатывание соответствующей цели. Не отправлять реальные персональные данные для теста.
6. Отозвать согласие через футер; после перезагрузки аналитика не должна загружаться.
7. Проверить сборку `npm run build`, `npm run lint` и работу сайта в браузере.

## Перед запуском — юридический контроль

Политика в `src/app/privacy/page.tsx` на текущем `main` упоминает **Supabase** и только **Umami**, а также содержит утверждение, что данные не передаются третьим лицам. До публикации новой аналитики нужно проверить фактическую инфраструктуру и привести политику / согласие в соответствие с использованием Яндекс Метрики, Umami и Beget; обеспечить корректное информирование о целях, составе данных, сервисах и возможности отказа. При необходимости уточнить сведения в уведомлении РКН. Этот технический PR не заменяет юридическое согласование документов.
